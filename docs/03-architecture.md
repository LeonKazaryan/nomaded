# 03 · Архитектура

## Стек и почему

| Что | Выбор | Почему |
|---|---|---|
| UI | SwiftUI | Современный стандарт Apple, лучшие встроенные анимации |
| 3D | Metal, свой рендер | RealityKit на iPhone не рисует чаще 60 fps, а Metal даёт 120 на ProMotion (ADR-010). Нам нужны только цветные треугольники, всю математику мы и так считаем сами |
| Состояние | `@Observable` (Observation, iOS 17+) | Просто, быстро, без лишних фреймворков |
| Хранение | SwiftData | Нативно, мало кода, позже можно включить синхронизацию через iCloud |
| Графики | Swift Charts | Встроенный, анимируется |
| Поиск городов | MapKit `MKLocalSearchCompleter` | Бесплатно, без ключей и серверов |
| Тесты | Swift Testing | Современный фреймворк тестов, встроен в Xcode 16 |
| Зависимости | нет | Меньше рисков. Новая зависимость только через запись в журнале решений |

## Структура кода

Папки создаём по мере появления кода (git не хранит пустые папки).

```
Nomaded/
├── App/                  точка входа, корневой экран, сборка зависимостей
├── Features/             экраны; каждая фича — своя папка
│   ├── Globe/            экран глобуса: жесты, оверлеи, связь с движком
│   ├── CountryCard/      шторка страны и поездки
│   ├── MyWorld/
│   ├── Countries/
│   ├── Statistics/
│   └── Onboarding/
├── GlobeEngine/          всё 3D: сцена, меши, материалы, камера, hit-test. Без SwiftUI-экранов
├── Domain/               модели и чистая логика: Country, Continent, StatsCalculator
├── Data/                 SwiftData-модели, WorldStore, загрузка каталога стран
├── DesignSystem/         Palette, Typography, Motion, Haptics, общие компоненты
└── Resources/            Assets, String Catalog, countries.json, геоданные
NomadedTests/             тесты Domain и математики GlobeEngine
Tools/GeoPipeline/        утилита: Natural Earth → готовые меши стран (Swift Package, не входит в приложение)
```

### Слои и правила зависимостей

```
Features ──▶ DesignSystem
   │
   ├──────▶ GlobeEngine ──▶ Domain
   │
   └──────▶ Data ─────────▶ Domain
```

- **Domain** ни от чего не зависит: ни SwiftUI, ни SwiftData, ни Metal. Чистые типы и функции, полностью покрываются тестами.
- **GlobeEngine** ничего не знает про экраны и SwiftData. Наружу отдаёт маленький API (ниже). Поэтому технологию рендера можно заменить, не трогая фичи.
- **Features** склеивают всё вместе. Логику, которую можно протестировать, выносим из View в Domain.

## Паттерн: «MV» на `@Observable`

Без тяжёлых MVVM/TCA. Для приложения такого размера это лишняя церемония.

- **View** — разметка + локальное UI-состояние (`@State private`).
- **Store** (`@Observable @MainActor final class`) — общее состояние и действия. Передаётся через `.environment(...)`.
- **Domain-функции** — расчёты (статистика, проценты, группировки).

```swift
@Observable @MainActor
final class WorldStore {                         // Data/WorldStore.swift
    private(set) var visitedCodes: Set<String> = []

    func markVisited(_ code: String) { … }     // пишет Visit в SwiftData и сразу сохраняет
    func unmarkVisited(_ code: String) { … }   // удаляет все поездки в страну
}
```

- Создаётся один раз в `NomadedApp` и раздаётся экранам через `.environment(world)`. Глобус подписан на `visitedCodes` (`onChange`), поэтому отметка с любого экрана сразу видна на глобусе.
- Сохраняем сразу после каждого действия, а не ждём автосохранения: иначе отметка теряется, если приложение убить через секунду (так делает кнопка Stop в Xcode).
- Отладочные запуски с аргументами `-NomadedDebug…` работают на пустом хранилище в памяти и не трогают отметки, сделанные руками.

Статистика **никогда не хранится**, она всегда вычисляется из поездок (`StatsCalculator`). Значит, она не может разойтись с данными.

## Модель данных

### `Country` — статический каталог (Domain)
Хранится в бандле приложения (`Resources/Geo/countries.json`), пользователь его не меняет. Файл генерирует `Tools/GeoPipeline --catalog` из тех же данных Natural Earth, что и глобус, поэтому коды совпадают один в один (это проверяет тест). `CountryCatalog.bundled` грузится при первом обращении.

| Поле | Пример | Заметка |
|---|---|---|
| `code` | `"IT"` | ISO 3166-1 alpha-2, главный ключ везде |
| `continent` | `.europe` | enum из 7. Острова «открытого океана» Natural Earth разложены по геосхеме ООН (Сейшелы → Африка) |
| `subregion` | `.southernEurope` | enum, 23 подрегиона ООН M49 |
| `isSovereign` | `true` | одна из 195 (193 члена ООН + Ватикан + Палестина, список в пайплайне) |
| `areaKm2` | `300678` | по контурам Natural Earth. Для крупных стран точно, для микрогосударств грубо (Ватикан 0,01 км²), поэтому числом не показываем |

Точка, куда доворачивать камеру, лежит в `world.nmgeo` (`CountryShape.label`).

- **Название не храним.** `Locale.current.localizedString(forRegionCode: "IT")` даёт «Италия» / «Italy» / «Italien» на любом языке системы, бесплатно.
- **Флаг** вычисляется из кода (regional indicator symbols → 🇮🇹).

### `Visit` — поездка пользователя (SwiftData `@Model`)

| Поле | Тип | Заметка |
|---|---|---|
| `id` | `UUID` | |
| `countryCode` | `String` | → `Country.id` |
| `startDate` | `Date?` | `nil` = «был, но не помню когда» |
| `endDate` | `Date?` | |
| `cities` | `[String]` | не используется: города живут в `VisitedCity`. Оставлено, чтобы хранилище на уже установленных копиях открывалось без миграции |
| `note` | `String` | |
| `createdAt` | `Date` | для сортировки и «самая свежая» |

- Страна посещена ⇔ у неё есть ≥ 1 `Visit`. «Отметить» создаёт `Visit` без дат.
- «Снять отметку» удаляет все поездки и города страны. Если городов нет, без вопросов. Если есть, сначала подтверждение («3 города удалятся вместе с ней»). Когда у поездок появятся даты и заметки, то же правило для них.

### `EarnedMilestone` — полученная веха (SwiftData `@Model`)

`id` (`Milestone.id`: `"countries.25"`, `"continent.asia"`) и `earnedAt`. `unmarkVisited` в том же сохранении удаляет вехи, которых оставшиеся отметки больше не достигают, а при запуске убираются оставшиеся с прошлых версий. Повторное достижение празднуется снова. `WorldStore.earnMilestones()` вызывается в момент праздника отметки и возвращает новые вехи в порядке показа. При запуске он тихо засчитывает всё, что уже достигнуто. Правила в `Domain/Milestone` (`MilestoneRules`), покрыты тестами.

### `VisitedCity` — город (SwiftData `@Model`)

| Поле | Тип | Заметка |
|---|---|---|
| `id` | `UUID` | |
| `name` | `String` | как его назвал MapKit на языке пользователя («Рим») |
| `region` | `String` | область/штат, чтобы различать тёзок. Может быть пустым |
| `countryCode` | `String` | → `Country.id` |
| `latitude`, `longitude` | `Double` | где ставить точку на глобусе |
| `createdAt` | `Date` | порядок: в карточке новые первыми |

- Город добавляется через `WorldStore.addCity` и **сам отмечает страну** посещённой. Удаление города страну не снимает.
- Один и тот же город дважды не сохраняется: та же страна и ближе 10 км (`CityMath.sameCityKm`), потому что поиск может вернуть «Рим» в разных точках.
- Добавление новой сущности — лёгкая миграция SwiftData. Тест открывает хранилище «до городов» с новой схемой.
- **Сразу делаем модель совместимой с CloudKit**, чтобы в v1.1 включить iCloud-синхронизацию без миграционной боли: у всех свойств есть значения по умолчанию или они опциональные, никаких `@Attribute(.unique)`, связи опциональные.

## Геоданные

- **Источник:** [Natural Earth](https://www.naturalearthdata.com/) Admin 0 Countries **1:10m**, версия границ (worldview) **«USA»**, v5.1.2, Lakes и Rivers (scale rank) 1:10m. Public domain, можно использовать в коммерческом приложении. Почему так, см. ADR-005 и ADR-008.
- **Пайплайн `Tools/GeoPipeline`** (подробно в его [README](../Tools/GeoPipeline/README.md)): GeoJSON → вырезание озёр → упрощение с сохранением общих границ (~2 км) → раскраска соседей в 6 слотов → триангуляция (earcut + перевороты рёбер до Делоне) → укладка на сферу → реки по странам → `Resources/Geo/world.nmgeo` (формат v4: 6.3 МБ, 239 стран, 530 озёр, 1 810 рек, 197k треугольников). Пайплайн детерминирован. Треугольники режутся в плоскости lon/lat, а не по большим кругам: иначе на севере меш вылезал за побережье. Приложение **не парсит GeoJSON в рантайме**.
- **Крошечные страны** (Ватикан, Монако, Мальдивы, Науру…) на глобусе почти не видны. Сейчас тап рядом с ними прощает промах в радиусе 14 pt. В M4 добавим точки-маркеры.
- **Известное ограничение:** заморские территории (Французская Гвиана, Реюньон, Шпицберген и т.п.) в данных admin-0 входят в метрополию и красятся вместе с ней. Решаем в M3: Natural Earth «map units» делит их по собственным ISO-кодам.

## Глобус (`GlobeEngine`)

### Публичный API (`GlobeController`)

```swift
@Observable @MainActor
final class GlobeController {
    var onCountryTap: (@MainActor (String?) -> Void)?   // nil = тап в океан
    var countryCodes: [String]                           // все выбираемые страны (после isReady)
    func setVisited(_ codes: Set<String>)                // цвет + подъём, с анимацией
    func celebrate(_ code: String)                       // «прыжок» при Mark as visited
    func select(_ code: String?, framing: Framing)       // подсветка; .turn — доворот (тап), .flight — перелёт с зумом «по размеру» (поиск), .point — вплотную к городу
    func setCities(_ cities: [CityMarker])               // точки городов
    func landCity(_ id: UUID)                            // новый город «приземляется», когда камера долетит
    func highlightCity(_ id: UUID?)                      // его подпись видна всегда
    var onCityTap: (@MainActor (UUID) -> Void)?          // тап по точке города важнее страны под ней
    var cityLabels: [CityLabel]                          // подписи, уже разложенные без наложений
    var introStyle: IntroStyle                           // .arrival — прилёт из гиперпрыжка (онбординг); ставить до загрузки
    func frame(offset: Double, zoom: Double)             // поднять центр глобуса на offset pt и задать «зум покоя» (онбординг)
    func lookAt(_ code: String)                          // повернуть к стране без выделения
    func celebrate(_ code: String, quietly: Bool)        // quietly: полупрыжок без кольца
}
```

`GlobeCamera.centerOffset` сдвигает проекцию вверх целиком (`viewProjection`, `ray`, `screenPoint`), так что тапы и подписи городов работают и со сдвинутым глобусом.

### Как устроено (сделано в M1)

| Файл | Что делает |
|---|---|
| `GlobeController` | Сцена, покадровая физика (`tick`), анимации стран, жесты, интро |
| `GlobeCamera` | Вся математика «экран ↔ глобус»: фокусное расстояние, радиус силуэта, луч через точку экрана, ориентация (yaw/pitch) |
| `GeoMath` | lat/lon ↔ вектор, луч–сфера, point-in-polygon, углы |
| `WorldGeometry` | Загрузка `world.nmgeo` вне главного потока |
| `GlobeMeshes.rivers` + `riverVertex` | Реки лентами: каждая точка — две вершины, которые шейдер разводит поперёк реки на ширину в пикселях. Мягкий край через `fwidth`, рисуются по странам с их подъёмом и волной (блик) |
| `GlobeHitTester` | Какая страна под точкой (+ «прощение» для микрогосударств; тап по озеру — страна с ближайшим берегом) |
| `GlobeMeshFactory` | Меши: сфера-океан, страны, боковые стенки |
| `SpringValue` | Пружина для покадровых анимаций, в тех же терминах, что SwiftUI |
| `GlobeTuning` | **Все параметры ощущений** в одном месте: трение, пружины, высоты, зум |

- **Рендер (`GlobeRenderer`, `GlobeMetalView`, `GlobeShaders.metal`):** свой `CAMetalLayer` и `CADisplayLink`, который просит у экрана до 120 Hz. Каждый кадр: `tick` (физика), потом отрисовка. Шаг времени берётся по `targetTimestamp`, поэтому движение ровное при любой частоте. Фон слоя прозрачный, космос нарисован в SwiftUI (`SpaceBackground`).
- **Сцена:** все страны лежат в одном буфере вершин (`GlobeMeshes.pack`), каждая рисуется своим диапазоном индексов со своими `scale` и цветом. Плюс сфера-океан. Цвет плоский, без света, поэтому палитра отображается ровно как задумана. Сглаживание MSAA 4×, промежуточные буферы memoryless, то есть живут в памяти тайлов GPU.
- **Камера рендера** — та же `GlobeCamera`, что у тапов и оверлея (`viewProjection`). Тест проверяет, что точка под пальцем проецируется ровно туда, где нарисована.
- **Объём и атмосфера** рисуются не 3D-светом, а SwiftUI-оверлеем поверх глобуса: затемнение краёв, блик, свечение. Оверлей совпадает со сферой, потому что считается той же `GlobeCamera`.
- **Подъём страны:** меш лежит на сфере с центром в начале координат, поэтому `scale = 1 + lift` поднимает страну строго «вверх» от планеты. Боковые стенки прячутся внутри шара, так что щели не видно. Строятся вне главного потока сразу после появления глобуса.
- **Цвета:** у каждой страны есть цветовой слот из пайплайна, и соседи никогда не совпадают. Посещённые получают candy-цвет слота, остальные — один из 6 близких оттенков суши. Так границы читаются без линий.
- **Анимация страны** — это два числа в массиве `GlobeRenderer.pieces` (`scale`, `color`), которые уходят в шейдер. Ничего не пересоздаётся. На RealityKit смена цвета стоила ~0,5 мс за раз, и это давало просадки при выделении.
- **Тень стекла** (`.glass`) висит только на подложке. Если повесить `.shadow` на весь view, SwiftUI размывает отдельную тень под каждой буквой, флагом и иконкой внутри.
- **Жесты:** SwiftUI `DragGesture(minimumDistance: 0)`: касание сразу «ловит» крутящийся глобус, короткое касание = тап. Плюс `MagnifyGesture`. Вращение = yaw (вокруг полюсов) + pitch (наклон, с резинкой на ±69°), север всегда сверху. Отпустил → инерция с трением. Тап по стране → доворот на пружине. Система может отменить жест без `onEnded` (уход в фон, системный жест). Поэтому `GlobeView` следит за `@GestureState`, которые сбрасываются в любом случае, и зовёт `touchesEnded()`, иначе «залипший» drag или pinch глушил бы перелёты.
- **Зум и перелёты:** pinch держит точку между пальцами (`GlobeOrientation.placing`). Перелёт: круиз на отдалении → доворот → зум «по размеру страны» (`GeoMath.capRadius` без далёких частей вроде Французской Гвианы + `GlobeCamera.distance(fitting:)`). Затенение глобуса — `Canvas` размером с экран, потому что вблизи глобус в десятки раз больше экрана.
- **Города на глобусе:** точки рисует Metal одним instanced-проходом поверх суши: квадрат, повёрнутый к камере, а в шейдере белая сердцевина, ободок цвета страны, тёмная обводка, свечение и кольцо «приземления». За горизонтом точка плавно гаснет (проверка в вершинном шейдере), поэтому буфер глубины ей не нужен. Данные точек лежат в кольце из трёх буферов, по одному на кадр «в полёте». Подписи — SwiftUI поверх глобуса. Их раскладывает движок (`CityLabelLayout`: жадно по приоритету, без наложений, с зума `cityLabelZoom`). Чтобы подписи не отставали от глобуса на кадр, Metal-слой показывает кадр в той же транзакции Core Animation, что и SwiftUI (`presentsWithTransaction`).
- **Справочник городов** (`Domain/CityCatalog`, `Resources/Geo/cities.json`, 1,2 МБ): ~7 300 населённых пунктов Natural Earth с населением, координатами, признаком столицы (`ADM0CAP`) и названиями en/ru. GeoPipeline собирает его (`--places … --cities …`), коды стран те же, что у глобуса. Грузится в фоне при старте. Нужен для поиска (ранжирование «точное → начало → начало слова», внутри — по населению) и для звёзд столиц (город ближе 25 км к столице своей страны).
- **Поиск городов** (`Features/Cities/CitySearch`): сначала результаты справочника (мгновенно, офлайн), потом MapKit `MKLocalSearchCompleter` с фильтром только городов (`MKAddressFilter(.locality)`, iOS 18). Два режима: весь мир (вкладка «Города» в общем поиске `SearchPanel`) или строго одна страна («+ Город»: регион страны с `regionPriority = .required`, плюс фильтр по названию страны в подписи, плюс проверка кода страны у найденного места). Названия на языке пользователя, без ключей и разрешений. Общие куски: поле `SearchField` (DesignSystem) и список `CityResults` с состояниями «нет связи / другая страна / нет на глобусе».
- **Статистика** (`Domain/WorldStats`, `Features/Statistics`): `StatsCalculator.stats(visited:catalog:)` считает всё из посещённых кодов и справочника, ничего не хранится. Страны и территории везде делит одна функция `CountryCatalog.split`: её используют счётчик сверху, список посещённых и статистика. `StatsCalculator.places(on:visited:catalog:)` раскладывает страны континента (или всего мира при `nil`) на открытые и неоткрытые, территории отдельно. Один экран-список `PlacesDetail` показывает и континент, и весь мир, а шапку (карту или карточку с кольцом) ему передают снаружи. Мини-карты континентов (`ContinentMaps`) — ортографическая проекция контуров глобуса вокруг центра континента, считается один раз в фоне после загрузки глобуса. Пока статистика открыта, глобус на паузе (`GlobeController.isPaused`): кадр не перерисовывается, и стекло над ним дешевле.
- **Поиск** (`Domain/CountrySearch`): индекс названий на языках пользователя + английский + словарь бытовых имён; ранжирование: точное → начало → начало слова → вхождение. Покрыт тестами.
- **Hit-test математикой:** точка экрана → луч → пересечение со сферой → lat/lon → bounding box → point-in-polygon. Покрыт тестами на реальных городах.
- **Праздник отметки:** волна заливки и кольцо — в шейдере суши и океана. У каждой страны в `DrawUniforms` есть «цвет внутри / снаружи волны», её центр и радиус. В `FrameUniforms` лежит кольцо: центр, пройденное расстояние, цвет и сила. Фрагмент считает угловое расстояние до центра (`acos(dot)`). Конфетти — SwiftUI `Canvas`, где положение каждой бумажки вычисляется по формуле из времени, без шагов и хранения. Штамп — SwiftUI-вид в карточке. Страну, которую отмечает приземляющийся город, движок держит «неотмеченной» до касания (`awaitingMark`).
- **Дальше (M4):** маркеры микрогосударств.

## Конкурентность (Swift 6)

- Проект в режиме **Swift 6**: компилятор строго проверяет гонки данных.
- Всё, что трогает UI, сторы и рендер глобуса, — `@MainActor`.
- Тяжёлое (декодирование мешей, первичная загрузка каталога) — в `async`-функциях вне главного потока, результат возвращаем на main.
- `@unchecked Sendable` и `nonisolated(unsafe)` — только с комментарием, почему это безопасно.

## Журнал решений (ADR)

Каждое значимое решение — строка здесь. Если решение меняется, не удаляем старое, а помечаем «заменено ADR-xxx».

| # | Решение | Статус | Коротко почему |
|---|---|---|---|
| ADR-001 | Глобус на RealityKit, отдельный меш на страну, свой hit-test | **Заменено ADR-010** | Работал красиво, но на iPhone не выше 60 fps: публичной настройки частоты у RealityKit нет. Замер Leon: экран даёт больше 65 Hz, глобус ровно 60 |
| ADR-002 | iOS 18+, только iPhone, только портрет | Принято | `MeshGradient`, zoom-переходы, `@Previewable`. Без iPad проще дизайн и релиз |
| ADR-003 | SwiftData, только на устройстве, модель совместима с CloudKit | Принято | Минимум кода. iCloud включаем в v1.1 без миграций |
| ADR-004 | Без сторонних зависимостей | Принято | Меньше риска для первого приложения |
| ADR-005 | Natural Earth **1:10m** + упрощение в пайплайне (заменяет «1:50m») | Принято | Версии границ под разные worldview есть только в 1:10m. После упрощения до ~2 км детализация лучше, чем у 1:50m, а вес тот же |
| ADR-006 | Swift 6 language mode | Принято | Сразу пишем правильно, без миграции потом |
| ADR-007 | Навигация без `TabView`: глобус как базовый слой + плавающие элементы | Принято | Ощущение «карта и есть приложение», как в Zenly |
| ADR-008 | Границы: worldview «USA» из Natural Earth | **Предложено — решить до релиза** | Единственная версия без «дыр» на месте спорных территорий (в ISO-версии на месте Крыма и Кашмира пусто). Что в ней: Крым — Украина; Кашмир поделён по линии контроля; Западная Сахара, Косово и Тайвань — отдельно; Голаны — Израиль; регионы без ISO-кода — нейтральная суша. Названия стран системные от Apple. Это расходится с законами некоторых стран (Россия, Китай, Индия), поэтому до релиза выбираем: не публиковать там или делать региональные версии данных (Natural Earth даёт worldview для 30+ стран, пайплайн принимает любую) |
| ADR-009 | Объём глобуса — SwiftUI-оверлеем, цвет плоский, без света | Принято | Точные цвета палитры, полный контроль над «стилизованным» видом, дешевле 3D-освещения |
| ADR-010 | Глобус на Metal: `CAMetalLayer` + `CADisplayLink` до 120 Hz, один буфер на все страны, MSAA 4× (заменяет ADR-001) | Принято | Даёт 120 fps на ProMotion. От RealityKit мы брали только «нарисовать цветные треугольники камерой», а камеру, физику, перелёты и тапы и так считали сами. Свой шейдер упрощает будущую волну заливки. Цена: ~400 строк низкоуровневого кода в `GlobeEngine`, конфетти делаем не частицами RealityKit |
| ADR-011 | Онбординг поверх живого глобуса, а не отдельными экранами; глобус вписывается в место, которое оставляет шаг (`GlobeRoom`) | Принято | Первое впечатление — сам глобус: прилёт, заливка стран прямо при выборе. Шаги сообщают свои края через `onGeometryChange`, камера сдвигает центр (`centerOffset`) и зум пружиной, поэтому ничего не перекрывается на любом Dynamic Type. Флаг «пройден» — `@AppStorage("hasOnboarded")`, из-за него появился Privacy Manifest (`CA92.1`). Пользователи с отметками онбординг не видят |
| ADR-012 | Озёра — дыры в суше, вырезанные в пайплайне, а не отдельный слой в рендере | Принято | Сквозь дыру виден тот же океан, у поднятой страны вокруг озера сами появляются стенки, мини-карты статистики получают озёра даром, рендер и шейдеры не меняются, в рантайме ноль затрат. Цена — вычитание полигонов (Greiner–Hormann) в пайплайне и перевороты рёбер до Делоне, чтобы дыры не раздували меш. Тап по озеру выбирает страну с ближайшим берегом: для этого контуры озёр лежат в `world.nmgeo` отдельной секцией |
| ADR-013 | Реки — отдельный слой лент в Metal, разрезанный по странам в пайплайне | Принято | У реки нет площади, дырой её не сделать. Лента постоянной ширины на экране (вершинный шейдер) читается на любом зуме, а раздача по странам даёт подъём вместе с сушей и блик от волны заливки теми же uniform'ами, без нового состояния. Мелкие реки проявляются по рангу Natural Earth в зависимости от зума (`riverRanks` в `GlobeTuning`). Цена: ~150 лишних draw call'ов за кадр (по одному на страну с реками) и 42k точек |
